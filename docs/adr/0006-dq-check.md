# 0006. DQ 서킷 브레이크 vs 무중단 결정

## Context
DQ체크할 때 오염된 데이터가 들어왔을때 아예 파이프라인 중단 후 수동 처리 방식으로 갈 것인가?
아니면 무중단으로 플래그를 붙이고 슬랙 알림으로 엔지니어가 알도록만 할 것인가?

## Decision
먼저 서킷 브레이크 방식은 오염된 데이터가 아예 들어오는 것을 원천적으로 막을 수 있음
단 중단 후 원인 파악을 하고 개선 결정 사항은 분석팀, 백엔드팀 등과 논의를 통해 결정해야 함.
하지만 이 프로젝트에서는 임의로 오염데이터를 손상하는 것이라 원인도 자명하고 데이터 정책도 따로 0으로 업데이트 하는 것을 정책으로 삼음. 이 경우 중단 할게 아니라 자동화 로직을 넣어야 함
하지만 snowflake 데이터만 업데이트할 시 원천 디비와의 데이터 불일치가 발생->CDC 정합성 철학과도 맞지 않음

따라서 플래그를 붙여 슬랙 알림으로 이상 데이터 탐지만 하고 무중단으로 운용 후 해당 이상 데이터 분만 원천 디비에서 update 하여 자동으로 탐지되어 merge되도록 결정
