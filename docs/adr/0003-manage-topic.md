# 0003. kafka 토픽 관리

## Context
이 프로젝트에서 필요한 토픽은 postgre 테이블에 필요한 토픽과 커넥트 클러스터를 운영하기 위한 토픽이 필요함. 이들을 자동 생성할지, 수동 생성할지를 결정해야 함. 자동 생성 시 관리는 편하지만 파티션 수를 커스터 마이징하기 어렵고, 수동 생성 시 스크립트를 짜야하는 오버헤드가 있음

## Decision
커넥트 관리 토픽은 자동 생성하기로 결정함. 기본 파티션 수로 생성이 되며, 관리용 토픽인 만큼 프로젝트 핵심 관심사랑 거리가 멀어 기본 설정대로 감. 반면 실제 WAL 데이터 토픽은 파티션 개수에 따라 lag가 달라질 것이라 예측하여 수동 생성 후 튜닝을 통해 파티션 수를 결정하기로 함

단 여기서 기준은 단순 lag가 줄면 무한정 파티션을 늘리기 보다는 평균 트래픽 부하 기준 컨슈머가 처리할 수 있는 목표 처리량을 기준으로 파티션을 나눔

우선 개발 환경에서는 자동생성으로 처리
