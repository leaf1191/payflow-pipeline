# 0001. kc 커넥터 초기화 컨테이너 재시도 로직

## Context

kc 초기화 스크립트 관리를 어떻게 할것인가?

1안. 어짜피 처음에 초기화 하면 충분하니 간략하게 짜고 실패하면 수동 재시도
2안. 스크립트 안에 재시도 로직 넣고, 컨테이너 차원에서 재시도

## Decision
2안으로 채택
이유는 개발 환경 외에 성능 측정 환경 등 다양한 환경에 배포 자동화를 해야하는데, 그 때 일시적인 네트워크 오류 등으로 문제가 생길 때마다 수동 실행하기에는 너무 번거롭고, 예측 불가능함
또 추가로 알게 된 것인데, 커넥터 json 바뀔 때마다 자동 cicd로 커넥터 업데이트 해주려면 자동 재시도가 필요함

## Context2
그럼 무작정 재시도 하면 성공할 수 없는 작업을 무한 재시도 한다거나, 같은 작업을 반복해서 수행할 수 있는 것 아닌가?

## Decision2
재시도 횟수로 정함-> 이 경우 스크립트 문제 등으로 성공할 수 없는 작업이 영원히 실행되는 것을 방지함. 
다만 일시적 네트워크 장애가 시도횟수를 넘기면 그대로 끝나게 되는 문제가 발생-> 일시적인 네트워크 문제로 실패하는 경우가 대부분이라 생각되며 그정도는 5*3회 재시도로 대부분 해결 가능하다고 판단

이상적으로라면 문제 유형을 파악해 그때마다 다르게 해야하지만 복잡도가 너무 올라간다 판단하여 간략화 함

그외 http 요청에서 타임아웃을 설정하여 무한 대기를 방지
또한 이미 커넥터가 등록되었는지를 확인하여 멱등성 보장함
->하지만 이미 돌아가는 클러스터 내에서 json 업데이트 하는 상황도 고려하여 upsert 로직을 적용하여 멱등성을 보장함

## Context 3
재시도 하는 건 좋은데 set -u 옵션 등으로 스크립트 자체에 문제가 있다면 바로 컨테이너 재시도 횟수 3번 다까먹고 죽는 것 아닌가?
또한 재시도 해도 클러스터가 죽어 있다면 아무것도 못하고 재시도 횟수 초과되는 거 아닌가?

## Decision 3
set -u 옵션 등으로 죽을 경우 on_exit 함수를 만들어 과정을 로깅함, 3번 다 까먹고 죽지만 재시도로 고칠 문제가 아니니 로그로 남김
또 재시도 전에 클러스터가 살아있는지 체크하는 로직을 추가함, 무한정 실행되면 안되니 맥스 타임을 설정하고 폴링 주기를 두어 체크함. 실패시 바로 fatal 오류를 발생시켜 최대 정한 시간만큼 대기하도록 함
